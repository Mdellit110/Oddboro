- [staff] **Decision (2026-11-09): a lead can park work until a named task ends, and the task ending wakes it.** Work that waits on something the owner does, such as a task on their desk, had only a time to wait for, so the lead woke early or sat idle. The lead parks the work with `resume_at` and its `after_task`, the number of a task on other work that the lead gave or that is on work it is on, which sets the column `resume_on_task` on the thread and clears any time it was parked on; parking on a time with `resume_at` clears the task. Any other task reads as no task at all, so a park learns nothing of another Odd's task. When the task ends, `wakeOnTask` clears the park and wakes the lead once, telling it the task was finished or dropped and the owner's note. A dropped task wakes it too, and says it will not be finished, so the lead decides what comes of the work. A run on the task's own work picks up in the same moment (`OWN_RUN` says which ends start one), so each side is told of the other, or both do the parked work: that run names each parked work that picked up on its own and says to leave it to that work (`follow_ups.picked_up` on a `task_done` or `carry_out` run, or the answer that goes back on a drop, never the owner's note), and each parked work is told that run carries its own part. A task already on that work needs no park, since its answer already brings the lead back, and the tool says so. Stopping the work clears its park. The owner ruled this on 2026-11-09, and it extends the 2026-11-03 ruling that a lead parks work until a time.
