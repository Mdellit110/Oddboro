- [staff] **Decision (2026-11-09): a `hand_off` can carry named files, copied into the sender's part of the thread.** Work often depends on a file the sender holds, such as notes or a draft, and the colleague had only the brief to go on. The sender names up to five files (`HandOff.files`) that it can read, in its own folder or the folder of work it is on, and the office copies each into the sender's part of the thread's folder, where everyone on the thread reads it. `readableFile` decides what a sender can read, and an unreadable file, a full path or an instruction file refuses the hand-off with an error that says what to do, so nothing is handed off half-furnished. This reopens the 2026-11-02 ruling that files cross by copy only narrowly: a copy, never a link, and only what the sender can already read. The owner ruled this on 2026-11-09. Files a hand-off copies in fall under the 2026-11-03 rule that what an Odd sees through a thread is no wider than its access. Code in `packages/ledger/src/mcp.ts` (`readableFile`, `hand_off`), `packages/ledger/src/hand-offs.ts` (`carryFiles`, `handOff`) and `packages/ledger/src/threads.ts`.
