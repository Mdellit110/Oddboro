- [office] **Decision (2026-11-04): the office answers only at its own names (127.0.0.1, [::1], localhost, its addresses through Caddy and the app's ORIGIN), and takes an action (anything but GET, HEAD or OPTIONS) only from the owner's own page, with one exception: the app's shell reports updates with the token it gave the server.** Other pages open in the owner's browser can send requests to the office too, and only the owner's own page may act in their name. SvelteKit's own check covers form posts only, so the office checks every route and API request itself, in every mode; files built into the page are served before the check. The page is told apart by what the browser says (Sec-Fetch-Site, or with none an Origin naming the host asked), since through Caddy the page is https and the office http. The names refuse a site that points its own name at this computer. Vite's dev server route `/__open-in-editor`, which opens a file in an editor and runs before that check, is refused outright, since nothing in the office uses it. Code in `apps/office/src/lib/server/owner-page.ts` (`guardOffice`) and `apps/office/vite.config.ts` (`noEditorLaunch`).
