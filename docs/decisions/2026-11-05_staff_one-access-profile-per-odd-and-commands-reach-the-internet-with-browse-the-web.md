- [staff] **Decision (2026-11-05): what an Odd's runs reach is one profile, which its runs, `my_access`, `office_report` and the Access tab all read, and with Run commands and Browse the web both on, a Claude Code Odd's commands reach the internet but never this Mac's own addresses.** One profile means the prompt, the tool server and the page never disagree, and an Odd that may browse can also fetch what its commands need. `ownTools` in the ledger's `capabilities.ts` takes the stored switches and folders as the Odd's tool takes them: a shell (`runsCommands`), the web, whether commands reach the internet (`commandsOnline`), and the folders still on the disk. The page gets it as `reach` (`toProfile` in the office's `profile.ts`), and the Odds list shows it as chips. Commands reach the internet only where `NETWORK_WITH_WEB` says the tool's walls were measured holding with the network open: Claude Code (2.1.318), with every host allowed but this Mac's own addresses (`LOOPBACK` in `sandbox.ts`: localhost, 127.0.0.1, ::1, [::1] and 0.0.0.0), where the office's API and database listen; its proxy refused each, and names that resolve to them. The list matches exact hosts and resolved addresses, not ranges, so other 127.x addresses stay open; nothing answers there on a Mac unless the owner adds one. Codex's commands stay off the internet: with its network on, Codex 0.166's commands reached the office's API and database on this Mac, and no Codex setting was measured to shut them. Grok and Gemini run no commands. Claude Code's commands read what the run reads, their temp folder, node when it sits in the home folder, and the system's own folders outside `/Users` and `/Volumes`. Both tools' commands also read the owner's developer tool folders that exist, read only: `~/.npm`, `~/.nvm`, `~/.volta`, `~/.pyenv`, `~/.rbenv`, `~/.cargo`, `~/.rustup`, `~/.bun`, `~/.deno`, `~/go`, `~/.gradle`, `~/.m2`, `~/.gem` and `~/.local/bin`, with the folder of each link there that leads elsewhere in the home. They never read the credential files in them: `~/.cargo/credentials`, `~/.cargo/credentials.toml`, `~/.gradle/gradle.properties`, `~/.m2/settings.xml`, `~/.m2/settings-security.xml` and `~/.gem/credentials` (`devReads` in the office's `sandbox.ts`). A folder in or holding a secret store, the office's home or Oddboro's code is left out, and so is one whose real path holds `*`, `?`, `[` or `]`. `~/.docker` is left out: the docker CLI needs the daemon's socket, which the sandbox does not open. npm's user config names a file that is never made, so the owner's `~/.npmrc` is never read. A Claude Code that refuses the open network fails the run that met it, which tells the owner so, and the office records one Ledger line; its Claude Code runs then keep commands off the internet for the rest of that office run, which the line under Browse the web says, as do the prompt and `my_access` of a run that would have had it. The state is in memory, so a restart tries once more. Under a Run commands switch locked off because the Odd's tool cannot follow it, one click moves the Odd to a tool on this system that can, with the switch on; the move is refused before anything changes if that tool cannot. With Run commands on, Claude Code's run temp folder joins its working folders (`--add-dir`), so npm can keep its cache there: Claude Code's sandbox lets commands write only its own temp folder inside it. A change that opens or closes the internet to an Odd's commands says so in its Ledger line. This supersedes the 2026-11-04 ruling on commands, the web and folders where it said commands have no network and read only what the run reads. Code in the ledger's `agents.ts` and `capabilities.ts`, and the office's `sandbox.ts`, `profile.ts` and `staff.ts`; `apps/office/CLAUDE.md` item 9 lists the rules.
