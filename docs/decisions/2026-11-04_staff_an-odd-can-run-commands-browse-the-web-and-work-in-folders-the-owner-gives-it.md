- [staff] **Decision (2026-11-04): an Odd can run commands, browse the web and work in folders the owner gives it, each set per Odd on its Access tab, off by default, and held by each coding tool's own tools and walls.** Odds that build and research need a shell, the web and the owner's real projects, without a way out to the owner's keys. Under "Runs on" sit two switches, Run commands and Browse the web, and below them a Folders list, each folder typed as a path (no picker) and set to Can read or Can read and change. The stored switch is the owner's choice; whether a run gets a shell is worked out at each run from its tool and system (`commandsHow` in the ledger's `agents.ts`) and never written back. Claude Code follows the switch on a Mac, with `Bash` in its own sandbox: it reads only what the run reads (its folders, the node install, its temp folder, and the system's own folders outside `/Users` and `/Volumes`), writes only the folders the run writes, never the data folder or what the walls below refuse, has a temp folder of its own and no network, and sees none of the secrets in the run's environment: the API key, `DATABASE_URL` and every variable whose name says key, token, secret, password, credential, auth or cookie. Claude Code itself and the office's tool server keep them. Off a Mac it shows off ("Not tested on this system yet."). Codex shows on and locked, since it reads files through its commands; Grok shows off ("Grok can't keep commands off the network on a Mac."), and Gemini off ("Not tested with Gemini yet."). The staff PATCH refuses `{commands}` for a tool that does not follow the switch, so a stored yes is always the owner's own. Browse the web turns on each tool's own search and fetch: Claude Code's `WebSearch` and `WebFetch`, Grok's `web_search` and `web_fetch`, Codex's `web_search` (`live`, else `disabled`), and Gemini's `google_web_search` and `web_fetch`. What an Odd searches leaves the Mac by design, and the switch carries no warning line. Every tool's walls treat a granted folder as they treat the Odd's own folders: read, or read and written, with its instruction files never written, nor, in a granted folder alone, a repository's git hooks, config or submodules anywhere in it (`REPO_RUNS`), which git still reads. So no Odd can `git init`, `git clone` or update a submodule at a granted folder's top, and Claude Code cannot anywhere in it. Its own folder is the office's, where it may make a repository. Codex has two gaps: it keeps each write folder's own `.git` read only by itself, so a Codex Odd cannot commit in a granted repository; and a repository nested inside a granted folder is not covered for Codex, which takes a glob only to deny, and a deny stops git reading. A run of work another Odd handed over keeps this Odd's own Run commands, Browse the web and granted folders; the Draft cap on such runs covers outside tools only, since those are what leave the office. A folder deleted since it was given reaches no run. `checkFolder` refuses the home folder, anything outside it, and a folder that holds or sits in a secret store (`SECRET_STORES`, the list `unreadable` also reads), the office's home or Oddboro's code, each with one line the page shows under the folder field. It compares real paths as the disk spells them (`realpathSync.native`), so case, `~`, a link or `..` change nothing. `setFolder` also refuses a folder inside or holding one the Odd already has, since one would carry two levels; the same folder at another level replaces it. Every change is a Ledger line by the owner, like "Let Sam run commands" or "Took ~/notes from Sam", and takes effect on the Odd's next run. Code in `packages/ledger/src/office.ts`, `apps/office/src/lib/server/staff.ts` and `AccessTab.svelte`; `apps/office/CLAUDE.md` item 9 lists the rules.
