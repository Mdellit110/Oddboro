- [staff] **Decision (2026-11-05): each coding tool signs in through accounts, each a folder of its own under `~/.oddboro/accounts/<tool>/<id>`, which Odds share; every Odd starts on its tool's Office account and the owner can move it to another on its Model tab, and its chat carries on whatever tool, model or account it moves to.** One sign-in per tool kept two Odds from using two Grok, Codex or Claude logins. A run points its tool at the account's folder (`GROK_HOME`, `CODEX_HOME`, `CLAUDE_CONFIG_DIR`); Claude Code keeps each folder's login apart (on a Mac its keychain entry is named after the folder), so logins never overwrite each other. No run may read any account's folder but its own Claude sessions. The Office accounts move in at start: the Grok and Codex homes are renamed into `accounts/`, invisibly, with their sign-ins. Claude Code's Office account is new: a login cannot be copied safely (a refresh replaces the token, so two copies sign each other out), so until the owner signs it in, Claude Odds on it keep using the owner's own login, and Setup and the Model tab offer one-click sign-in; an office on an API key moves with no click. Shared accounts mean fewer sign-ins than one per Odd. The office's own chat record carries a conversation across a switch: a new session hears the latest of it word for word and is told where the rest is (`chat.jsonl` in its folder). Code in `packages/ledger/src/accounts.ts`, the tools' launches in `apps/office/src/lib/server`, and the Model tab.
